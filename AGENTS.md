# Правила для агента (CocktailCalc Pro)

## Главное

1. **Сервер не трогать.** Не запускать, не останавливать и не перезапускать веб-сервер самостоятельно. Только по явному запросу пользователя и только в крайнем случае. Пользователь запускает сервер сам через `start_server.command` (macOS) или `start_server.bat` (Windows).

2. **Микроправки вместо переписывания.** Не переписывать код целиком и не делать лишних изменений. Точечные правки — только то, что нужно для задачи. Это экономит трафик и токены. Никаких рефакторингов «заодно», форматирования и переименований без запроса.

3. **Не коммитить и не пушить без команды.** Контроль версий ведётся через Git, но любые `git commit` / `git push` — только по явной просьбе пользователя.

## Окружение

- Python — только из виртуального окружения `.venv` в корне проекта. В системный Python ничего не устанавливать.
- Зависимости: `.venv/bin/pip install -r requirements.txt` (и только при необходимости).

## Проект

- Веб-интерфейс: FastAPI, точка входа `web/main.py` (`uvicorn web.main:app`).
- Telegram-бот: `bot/main.py`, токен через переменную `BOT_TOKEN`.
- Общее ядро расчётов: `cocktail_calc/` — используется и вебом, и ботом. Правки здесь влияют на оба интерфейса.
- База: `data/cocktails_db.json` — единый источник данных для веба и бота. Формат файла не менять без необходимости.

## Дополнительные рабочие правила

1. **НЕ читать бинарные файлы напрямую.** `.xlsx`, `.pdf`, `.docx` сначала конвертировать в CSV через pandas/openpyxl, потом читать CSV.

2. **НЕ выполнять несколько Shell-команд подряд без подтверждения.** После каждой команды — пауза, ждать результат.

3. **Не переписывать весь файл при ошибке.** Исправлять только конкретную строку.

4. **Лимит: максимум 3 итерации исправлений.** Если не получается — остановиться и описать проблему текстом.

5. **Перед запуском скрипта проверить:** файл существует? Права доступа? Кодировка UTF-8?

6. **НЕ использовать кириллицу в путях к файлам внутри кода.** Только латиница и snake_case.

7. **Сложная задача — разбивать на шаги.** Спрашивать подтверждение перед каждым шагом.

8. **Задавать наводящие вопросы и уточнять.** Если требование непонятно или двусмысленно — спросить, а не додумывать. Не делать того, о чём не просили.

9. **Согласовывать план перед исполнением.** Перед тем как писать/запускать код для нетривиальной задачи — кратко описать план действий и дождаться одобрения.
